# T22: правила времени Clock и Timer

Спецификация от 26 октября 2026 года. ClockService и приложение Clock используют описанные ниже правила времени, а MacLock читает совместимую проекцию и общий источник времени загрузки. Проверки включают моделирование сна, перезапуска и смены времени, а также изолированный niri. Timer-карточка в этот состав не входит.

## Семантика

Обычный Timer первого цикла — одна общая сессия Clock App, MacLock и всех Timer-карточек. Добавление виджета не запускает и не заменяет таймер. Новый preset при занятой сессии требует явного решения о замене. Несколько независимых таймеров добавляются позже с job ID; Pomodoro B03 получает отдельные job ID и не занимает обычный слот.

Источник длительностей в Linux — `time.clock_gettime_ns(time.CLOCK_BOOTTIME)`, миллисекунды от начала текущей загрузки, включая suspend. Идентичность загрузки — `/proc/sys/kernel/random/boot_id`. Календарное время (`CLOCK_REALTIME`, дата/зона) используется для будильников, подписей и совместимой проекции, но не для остатка активного Timer. Секундомер переводится на тот же источник длительностей отдельной проверкой; его laps и накопленное время сохраняются.

| Действие/событие | Переход и результат |
| --- | --- |
| start | Проверить длительность `1…604800000` мс и label ≤200 символов; создать новый session ID, сохранить total и deadlineBootMs = bootNow + duration. Состояние running. |
| pause | Сначала проверить истечение. Если срок ещё не прошёл, remainingMs = deadlineBootMs − bootNow, состояние paused, deadline снят. |
| resume | Для paused той же загрузки: deadlineBootMs = bootNow + remainingMs; running. Для recovery это отдельная команда пользователя. |
| cancel | Завершить текущую сессию без события сигнала; вернуть idle с последней длительностью. Повторная cancel — no-op. |
| finish | Единожды для session ID перевести timer в idle и сохранить событие завершения до его передачи UI/звуку. Оставить последний total/label для Repeat. |
| restart оболочки/helper в той же загрузке | Восстановить deadlineBootMs. Истёкший срок создаёт одно событие; неистёкший продолжает точный отсчёт. Paused сохраняет остаток. |
| suspend/resume | Время сна входит в длительность. Истёкший во сне срок даёт одно событие после возвращения, без цепочки повторных сигналов. |
| ручная смена часов/NTP/зоны | Остаток Timer не меняется; wall-clock проекция пересчитывается. Будильники продолжают использовать календарное время и свою политику повторов. |
| другая загрузка системы | Активная/приостановленная сессия получает recovery. Сохранённые данные и последний checkpoint остаются; автоматического запуска, истечения или сигнала по недостоверной wall-clock разнице нет. |
| recovery | В Clock показываются Resume saved remainder, Restart full duration и Cancel. Любое решение создаёт состояние с текущим boot ID; отсутствие решения оставляет сессию без отсчёта. |
| helper недоступен | Действия временно недоступны; UI показывает последний снимок как устаревший. После reconnect перечитывается авторитетное состояние. UI не создаёт второй таймер и не завершает его локально. |

## Владение, хранение и совместимость

Единственный ClockService владеет `macshell/clock.json`, включая сохранённые поля alarms/cities/sw/recents/snoozes/ringing и новую временную модель. Clock App отправляет команды, а не полный устаревший снимок файла. Патчи настроек используют ревизию, runtime-команды сериализуются владельцем. Процесс держит exclusive lock на отдельном постоянном `clock.lock`, который не заменяется и не удаляется при работе: блокировка самого атомарно заменяемого JSON привязана к старому inode и не защищает нового владельца. Второй владелец не запускает независимое расписание.

Каждая изменяющая команда имеет устойчивый UUID и хеш содержимого, не связанный с поколением соединения. При повторной доставке возвращается сохранённый результат без повторного действия; UUID с другим содержимым отклоняется. Журнал результатов хранится вместе с состоянием. Окно дедупликации — 10 минут CLOCK_BOOTTIME: неизменяемый envelope содержит boot ID и время выпуска, команды за пределами окна/из другой загрузки отклоняются. Неистёкшие результаты не вытесняются; предел 1024 записи означает отказ новой команде busy до освобождения места, а не риск повторного выполнения. После reboot/истечения окна клиент перечитывает состояние и не повторяет старое действие автоматически. Проверка revision/CAS и session ID предотвращает применение старого pause/cancel к новому таймеру. Transport request ID сам по себе не обеспечивает идемпотентность после reconnect.

Новый документ имеет `version: 2`, `revision` и `timing` с собственным `version: 1`. Неизвестные поля сохраняются. Прежние top-level `timer`, `sw`, `ringing` остаются совместимой проекцией для старых читателей; каноническое время хранится в `timing`. Повреждённый/будущий файл не перезаписывается автоматически, перед первой миграцией сохраняется точная копия.

Пример канонического активного таймера:

```json
{
  "version": 2,
  "revision": 12,
  "timing": {
    "version": 1,
    "bootId": "example-current-boot-id",
    "timer": {
      "sessionId": "example-session-id",
      "state": "running",
      "totalMs": 300000,
      "deadlineBootMs": 1300000,
      "remainingCheckpointMs": 240000,
      "checkpointBootMs": 1060000,
      "label": "Tea"
    },
    "completion": null
  },
  "timer": {"state": "running", "total": 300000, "endAt": 1800000240000, "left": 240000, "label": "Tea"}
}
```

Состояния paused/recovery сохраняют `remainingCheckpointMs` и не имеют действующего deadline. Для recovery совместимая проекция имеет `timer.state = "paused"` и `recoveryRequired = true`; старый MacLock не начинает неверный отсчёт. Новый MacLock показывает требование восстановления.

В recovery остаток running-сессии является последним сохранённым checkpoint, а не точным остатком в момент отключения питания. Возраст checkpoint в работающей системе — до 30 секунд; после сбоя/неуспешной записи он может быть больше и показывается явно. Paused сохраняет точный подтверждённый остаток. Возобновление не вычисляет «пропущенное» время по настенным часам.

Запись происходит атомарно при действиях/переходах и при checkpoint активной сессии не чаще раза в 30 секунд. Нет записи на каждом кадре или периодического чтения настроек в простое. `endAt` пересчитывается при переходе, обнаруженной смене wall-clock и checkpoint; он не является источником elapsed time.

Новый MacLock использует канонический deadline и тот же kernel clock через один общий read-only time provider для всех своих outputs. Он не записывает `clock.json` и не создаёт собственную сессию. Clock App и desktop-карточки получают время/состояние от ClockService. IPC stop/snooze сохраняет совместимые команды; восстановление после reboot выполняется через владельца.

Проекция сохраняет читаемость старого MacLock, но его `Date.now()` не становится точным kernel clock: при скачке часов до обновления файла возможна неверная подпись. Полная временная приёмка требует обновления MacLock вместе с ClockService. Закрытие/отключение окна приложения или удаление последней карточки не отменяет уже запущенные задания. Служба работает в живом сеансе MacShell; самостоятельная работа после выхода из сеанса пока не обещается. Suspend не означает аппаратное пробуждение по RTC: сигнал выдаётся после возвращения системы.

## Календарные будильники и snooze

По умолчанию будильник следует текущей системной зоне; собственная зона требует явного отдельного поля. Для пропущенного времени при весеннем DST выбирается первый действующий момент после разрыва; при повторе осеннего часа — первое вхождение. Устойчивый occurrence ID включает alarm ID, локальную дату и выбранную зону/правило; смена зоны или перевод часов назад не повторяет уже обработанное календарное срабатывание того же будильника в этот локальный день. Изменение расписания задаёт новую ревизию правила, но не повторяет уже обработанный день автоматически.

После suspend/перевода часов вперёд/перезапуска сеанса в той же загрузке пропущенное срабатывание не старше 15 минут даёт одно событие; более старые получают отметку missed без неожиданного звука. Для нескольких пропусков одного будильника выбирается только последний. Сохранённые occurrence ID проверяются до постановки звука в очередь. Эти правила показываются в справке Clock и проверяются на моделируемых датах/зонах.

Snooze — длительность от подтверждённого действия пользователя: тот же CLOCK_BOOTTIME + boot ID, а не дата `Date.now() + delay`. Смена часов не влияет на snooze; после другой загрузки автоматического сигнала по сомнительной разнице нет, остаётся информация о пропущенном событии. Пока секундомер не переведён на kernel clock, T23 нельзя считать завершённым; перенос включает laps, pause и recovery без выдуманного elapsed после reboot.

## Миграция и события

Старый running `endAt` мигрирует один раз: `remaining = clamp(endAt − wallNow, 0, total)`, затем создаётся deadline текущей загрузки. Восстановить влияние прежней смены часов на старый timer достоверно нельзя; это фиксируется как provenance миграции. Повторная загрузка документа v2 остаток заново из `endAt` не выводит.

Событие завершения имеет устойчивый event ID, связанный с session ID. Переход timer→idle и создание события записываются одной заменой файла. Повторные tick/reconnect/restart не создают новое событие. UI и звук дедуплицируют event ID; claim звукового события сохраняется до запуска воспроизведения, визуальное неподтверждённое уведомление остаётся до Stop/Repeat. Сбой между claim и физическим запуском звука не объявляется гарантированным воспроизведением: автоматический повтор звука после такого сбоя не выполняется. Сигналы будильника и таймера используют последовательную очередь, не затирая друг друга.

## Приёмка T23/T24

Проверяются start/pause/resume/cancel/finish, повторные и одновременные команды, обе смены системного времени, suspend с истечением/без истечения, restart в той же загрузке, другой boot ID и три решения recovery. Отдельно — миграция старого endAt/paused, повреждённый и будущий формат, обрыв записи, смерть helper, одинаковый event ID после reconnect и совместимая проекция.

Обязательны повтор одного UUID до/после reconnect и рестарта, тот же UUID с другим payload, конфликт revision и два владельца при atomic replace. Для будильников — весенний gap/осенний fold, смена зоны и часов в обе стороны, граница 15 минут и несколько пропусков; для snooze — suspend, скачок часов и reboot. Проверяется независимость MacLock от рестарта оболочки.

Регрессии подтверждают alarms/snooze/stopwatch/laps и работу при закрытом Clock, скрытых/удалённых карточках и активном MacLock. Kernel-time сценарии моделируются без изменения часов/сна пользовательской сессии; native niri проверяет UI, ввод и общий сигнал в изолированном окружении.

1 ноября 2026 года в установленном сеансе Niri (MacShell) проверены реальные нажатия виртуальным указателем: добавление карточки Timer, запуск, пауза и продолжение, подтверждённая замена, пауза в Clock с отображением на карточке и продолжение/остановка с карточки. Тестовый таймер остановлен, карточка удалена. Две карточки, удаление при работающем таймере и однократное завершение отдельно проверены автоматизированным тестом в изолированном вложенном niri; реальную парольную разблокировку MacLock эта проверка не подтверждает.
