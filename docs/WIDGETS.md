# Галерея виджетов

Откройте **Settings → Widgets**. В General также есть кнопка **Open gallery…**. Поиск понимает `виджеты`, `погода`, `календарь`, `часы`, `плеер`, `батареи`, `заряд`, `устройства`, `размер`, `город`.

Переключатель в заголовке скрывает все desktop-карточки и отражения в стекле. Раскладка сохраняется, список и оформление можно редактировать. Повторное включение возвращает карточки; Arrange доступен при включённых виджетах. Таймеры и будильники приложения Clock продолжают работать.

1. В **Add widgets** выберите **Weather**, **Calendar**, **Clock**, **Player**, **Activity** или **Batteries**.
2. Посмотрите **Small / Medium / Large**, выберите оформление и нажмите **Add widget**. Если экранов несколько, сначала выберите **Add to display**.
3. Нажмите **Arrange…**. Окна приложений закроются фоном рабочего стола, виджеты останутся сверху. Перетаскивайте карточки; размер выбирается в верхней полосе, действия — в **More** или правой кнопкой. Завершите **Done** или **Escape**.

Добавление и действия на рабочем столе сохраняются через один сервис. Во время записи повторные изменения блокируются, результат показывается в галерее. Переключение типа, размера и стиля в Add widgets меняет только предпросмотр. Если размер не помещается, галерея объяснит отказ; можно выбрать меньший размер или освободить место.

## Мои виджеты

По умолчанию открывается **My widgets**. Здесь перечислены все сохранённые карточки, включая не поместившиеся, карточки отключённых экранов и неизвестные типы. Выберите строку: ниже появятся настройки этой карточки. Размер и стиль сохраняются отдельно для выбранного ID. **Appearance…** открывает тонкие параметры с предпросмотром, **Apply** и **Cancel**; неподдерживаемые параметры скрыты.

- **Duplicate** создаёт новый ID и глубокую копию настроек на том же экране. Если места нет, исходная карточка сохраняется без изменений.
- **Move to display** переносит и неразмещённые карточки на доступный экран. Отключённый экран не подменяется первым подключённым: нужен явный выбор.
- **Remove** удаляет выбранную карточку. **Undo removal** восстанавливает её ID, настройки и желаемую позицию; несколько удалений отменяются в обратном порядке. Изменения других карточек и общих параметров сохраняются. Если экран отключён или заполнен, запись восстанавливается как неразмещённая.

Undo доступен до закрытия редакторов Settings/Arrange; Reload и Reset очищают историю. История появляется после успешной записи. При конфликте Undo сохраняется для повторной попытки с актуальным состоянием; чужой экземпляр с тем же ID не перезаписывается. Неизвестную запись можно явно удалить и восстановить, её настройки не интерпретируются.

Редактор внутри настоящего Settings в niri с изолированными демонстрационными карточками: [тёмная тема](images/widgets-settings-dark.png), [светлая тема](images/widgets-settings-light.png).

Предпросмотр использует настоящие компоненты с демонстрационными данными: без запросов погоды, MPRIS, загрузки обложек и доступа к пользовательским данным. Часы и календарь в нём остановлены. Liquid Glass показывается упрощённо, без чтения обоев.

## Оформление и данные

У **Clock → Appearance… → Seconds** три режима: **Smooth (default)** сохраняет прежнее движение секундного индикатора, **Once per second** обновляет его раз в секунду, **Hidden** оставляет статичный циферблат и минутное время. Настройка действует только на выбранную карточку и её отражения; preview остаётся остановленным. [Тёмная тема](images/widgets-clock-seconds-dark.png) · [Светлая тема](images/widgets-clock-seconds-light.png).

**Appearance…** работает с локальным черновиком. Выбор темы, шрифта, размера текста, плотности и тонировки меняет только демонстрационный preview. **Apply** сохраняет все эти поля одной операцией; **Cancel** отбрасывает черновик. Смена карточки или закрытие Settings также отбрасывает неприменённые изменения. Размер, перенос и основной выбор Style по-прежнему сохраняются сразу; если они изменили настройки выбранной карточки при открытом черновике, Apply отклоняется с сохранением черновика. Cancel перечитывает актуальное состояние. Изменения других карточек не откатываются.

- **Theme → Follow shell / Light / Dark** доступна для Liquid Glass всех типов, Normal Calendar, Normal Activity и Normal Batteries. У Weather Normal сохраняется погодный градиент; Light/Dark Clock и Player задаются самим стилем.
- **Font → Follow shell font** наследует шрифт Appearance оболочки. Можно выбрать Inter, Noto Sans, системный sans или monospace. Отсутствующий шрифт использует обычный fallback Qt; пользовательское имя из файла сохраняется в списке.
- **Text size → Default / Small / Large / Extra large** задаёт коэффициенты 1 / 0,9 / 1,1 / 1,2. В ограниченных ячейках текст подбирает размер или сокращается, сохраняя границы S/M/L.
- Только **Player** имеет **Content density → Default / Compact / Comfortable** и **Tint → From artwork** либо выбранный цвет. Плотность меняет масштаб содержимого, сохраняя размер карточки; текстовый размер настраивается отдельно.

В **Style** появился пункт **Default (…)**, возвращающий общий стиль этого типа. **Reset appearance** сбрасывает известные переопределения стиля, темы, шрифта, размера текста, плотности и цвета только в черновике; для сохранения нужен Apply. ID, позиция, размер и дополнительные неизвестные поля сохраняются. У прежних Calendar явный mode продолжает действовать, пока пользователь не выберет Follow shell или Reset. После сброса старый mode не удерживает карточку в тёмной теме.

Явные тема и шрифт меняются независимо у каждой карточки; общая тема и шрифт действуют на наследующие поля. Те же параметры получает отражение виджета в стекле панели. Источники Weather/Player остаются общими: отдельный город или отдельный плеер здесь не задаются.

Примеры тонких настроек: [светлая тема](images/widgets-appearance-native-light.png), [тёмная тема](images/widgets-appearance-native-dark.png). Это нативная отрисовка в niri с демонстрационными данными (`check-theme-native.py`, файлы `theme-player-appearance-*.png`); `preview-widgets.sh` также создаёт упрощённые portable-примеры `widgets-appearance-*.png`.

| Тип | Оформление | Данные |
| --- | --- | --- |
| Weather | Liquid Glass, Normal | Общая локация и единицы всех карточек Weather |
| Calendar | Liquid Glass, Normal; Follow shell/Light/Dark | Локальная дата |
| Clock | Liquid Glass, Light, Dark | Локальное время компьютера |
| Player | Liquid Glass, Light, Dark | Один общий активный MPRIS-плеер и источник текстов |
| Activity | Liquid Glass, Normal; кольца или графики | Общий SystemStats: CPU, память, выбранные интерфейс и диск |
| Batteries | Liquid Glass, Normal; автоматический/ручной выбор | DisplayDevice ноутбука и известные Bluetooth-устройства |

В **Shared weather settings** находятся общие параметры Weather: Automatic/City, название города и Celsius/Fahrenheit. Они действуют на все карточки Weather; пример в галерее остаётся демонстрационным.

## Desktop Activity

Добавьте **Activity** в галерее. Карточка показывает CPU, память, сеть и диск; доступны S/M/L и стили Liquid Glass/Normal. В **My widgets → Appearance & metrics…** выберите хотя бы одну метрику и **Rings / Graphs**. Выбранные метрики сохраняют порядок; повторное включение добавляет метрику в конец. Preview использует демонстрационные данные, Apply сохраняет настройки одной карточки, Cancel отбрасывает черновик. Duplicate копирует метрики и оформление независимо. Reset appearance сбрасывает только оформление, сохраняя выбранные метрики и вид.

Кольца показывают долю CPU и занятой памяти. Для сети и диска показаны скорости в двух направлениях; они не выдаются за процент загрузки. Графики хранят последние 60 секунд. Пороги, палитра и единицы скоростей следуют общим [настройкам Activity](ACTIVITY_SETTINGS.md). Интерфейс, диск и интервал измерений общие для меню и всех карточек; состав метрик и вид выбираются отдельно у каждой карточки.

Первый замер дельт отображается как Measuring…, неизвестные значения — как «—», настоящий ноль — как 0. При пропаже свежих данных появляется Waiting for fresh data…. После сна/возобновления сборщик заново измеряет дельты; история содержит разрыв. Нажатие открывает подробное Activity на том же экране. В Arrange нажатие выбирает карточку для редактирования.

Карточки работают и при скрытом индикаторе Activity или отключённом меню-баре. Меню, desktop и отражения используют один sampler. Последний потребитель освобождает подписку; открытое подробное меню сохраняет сборщик. Скрытые карточки сохраняют снимок и приостанавливают обновления; при возвращении получают свежие данные.

[Тёмная тема](images/activity-widget-dark.png) · [Светлая тема](images/activity-widget-light.png). Все размеры и оба вида с демонстрационными данными: `bash scripts/preview-activity-widget.sh`.

## Batteries

Добавьте **Batteries** через Add widgets. Карточка поддерживает S/M/L, Liquid Glass/Normal и локальное оформление. В **My widgets → Appearance & devices…** выберите **Automatic** или **Choose devices**. Automatic показывает батарею ноутбука и подключённые известные Bluetooth-устройства. В ручном режиме можно выбрать до 16 устройств; порядок выбора сохраняется. Small показывает первые 2, Medium 4, Large 6; оставшиеся учитываются в «+N more devices».

Выбор устройств и оформление работают с демонстрационным preview и общим черновиком. **Apply** сохраняет настройки одной карточки, **Cancel** отбрасывает изменения, **Duplicate** копирует выбор независимо. Reset appearance сбрасывает оформление, сохраняя выбранные устройства. Пустой ручной список показывает No devices selected; отсутствие доступных источников в Automatic — No batteries available.

Известный заряд **0%** и **100%** отображается числом, неизвестный — **«—»** с Battery unknown. У ноутбука видны Charging/Fully charged. После отключения выбранного устройства, адаптера или Bluetooth-службы старый процент скрывается; отображается Disconnected, Bluetooth off или Unavailable. Выбранный ID сохраняется, возвращение устройства восстанавливает данные. До следующей встречи с источником после перезапуска отсутствующее устройство может иметь подпись Unavailable device. В памяти сохраняются названия до 64 последних известных записей, без сохранения заряда как актуального.

Bluetooth-адрес определяет ID независимо от имени и адаптера. Два одинаковых имени различаются суффиксом адреса; несколько записей одного адреса объединяются с приоритетом подключённой записи. Без адреса используется идентификатор из BlueZ path. Батарея ноутбука имеет устойчивый логический ID `laptop` и соответствует текущему displayDevice. Его начальное состояние ожидает [готовности UPowerDevice](https://quickshell.org/docs/v0.3.2/types/Quickshell.Services.UPower/UPowerDevice/).

Карточки, desktop и отражения используют одну read-only модель поверх существующих BatteryControl/BluetoothControl. Дополнительных процессов, опросов или Bluetooth discovery нет. Неактивная модель прекращает нормализацию и хранит последний снимок; редактор поддерживает актуальный список устройств и при скрытых карточках. Batteries пропускает клики к рабочему столу; действия с карточкой доступны в Arrange и Settings. Другие UPower-устройства остаются отдельным расширением.

[Тёмная тема](images/batteries-widget-dark.png) · [Светлая тема](images/batteries-widget-light.png). Снимки размеров и состояний используют демонстрационные данные: `bash scripts/preview-batteries-widget.sh`.

## Управление на рабочем столе

В обычном режиме фон и пассивные карточки пропускают клики. Activity открывает подробное меню нагрузки на экране своей карточки, включая отключённый меню-бар. Player принимает нажатия внутри своей карточки, когда доступен плеер; ограничения в четыре интерактивных экземпляра больше нет. Области ввода следуют перемещению, масштабу и видимости карточек. Скрытый, удалённый или недоступный Player освобождает ввод.

В **Arrange…** перетаскивание имеет приоритет перед кнопками карточки: нажатие Player выбирает его для редактирования и не запускает воспроизведение. Значок **−** также удаляет карточку. Размер, перенос на другой экран и удаление сохраняются сразу; выбор карточки и открытие окна ничего не записывают. При перемещении, изменении размера или удалении выбранной карточки выбор сбрасывается, чтобы действия не оставались привязаны к прежнему положению.

В **More** и меню по правой кнопке доступны **Duplicate**, **Remove** и **Undo removal**. **Configure…** завершает расстановку и открывает My widgets в Settings с выбранной карточкой. Вне Edit контекстные действия фоновых карточек не захватывают ввод.

В **Arrange** слой виджетов поднимается поверх обычных окон и закрывает их обоями, с нейтральным фоном при недоступном изображении. Сами окна и рабочие столы не перемещаются. Верхняя полоса высотой 40 px помещается над первой строкой сетки и скрывается при перетаскивании; отдельного окна управления нет. Она следует экрану выбранной карточки.

**Done** и **Escape** завершают режим, возвращают слой под окна и освобождают клавиатуру. Прежнее приложение получает фокус, если оно ещё существует на том же рабочем столе и пользователь не переключился в другое окно. В обычном режиме keyboard interactivity None; только активный экран Arrange запрашивает Exclusive для Escape. Изменение размеров/доступной области или отключение выбранного экрана завершает режим без переноса фокуса. Вход, выбор карточки и выход не записывают позиции; выполненные перемещения и размеры сохраняются сразу, отдельного Apply для раскладки нет.

Примеры с нейтральным фоном изолированного окружения: [тёмная тема](images/widgets-arrange-dark.png), [светлая тема](images/widgets-arrange-light.png). Проверка — `python3 scripts/check-widget-arrange-native.py --capture docs/images`; реальные клики и возврат фокуса — `python3 scripts/check-widget-input-native.py`. Запускайте native UI-проверки последовательно, чтобы их поверхности не перекрывали друг друга.

## Реестр и совместимость

[WidgetCatalog.js](../MacShell/WidgetCatalog.js) описывает шесть встроенных типов, компоненты, размеры, допустимые стили, интерактивность, настройки и необходимые данные. Галерея и desktop используют этот общий реестр; описания типов хранятся отдельно от размещённых экземпляров.

Файл остаётся `macwidgets/settings.json` внутри `MACSHELL_SETTINGS_HOME`; без этой переменной сохраняется прежний путь `~/.config/macwidgets/settings.json`. У установленной оболочки это `~/.config/macshell-niri/settings/macwidgets/settings.json`.

При первой загрузке прежнего файла выполняется миграция в версию 1. Сохраняются ID, S/M/L, Calendar mode, стили и дополнительные поля. Повторяющиеся старые ID получают устойчивые суффиксы, исходное значение остаётся в `legacyId`. Общие город, единицы и стиль читаются как defaults, а явно заданный стиль карточки имеет приоритет. Неизвестные типы и записи будущей версии не отрисовываются и сохраняются без изменения их содержания при последующих действиях.

Раскладка однократно привязывается к экрану, на котором прежняя версия показывала виджеты во время миграции. Если экранов нет, миграция ждёт их подключения. Перестановка списка экранов не переносит карточки на другой монитор. При отключении сохранённого экрана записи остаются в файле; галерея сообщает об этом.

Положение хранится как желаемые столбец и строка сетки. При уменьшении экрана возможен временный сдвиг; непоместившиеся карточки перечисляются в галерее. Изменение геометрии не записывает эти временные позиции. После возврата размера желаемое размещение восстанавливается. Явное перетаскивание сохраняет новую позицию.

## Несколько экранов

Каждый экземпляр привязан к своему профилю дисплея. На каждом подключённом экране используется отдельная сетка и собственные области ввода; зеркало в стекле панели также показывает только карточки этого экрана. Глобальные координаты и порядок мониторов не влияют на локальные позиции. Переход на другой разъём распознаётся по уникальному serial с совместимой моделью. При неоднозначной идентичности сохранённая раскладка ждёт однозначного подключения и не дублируется на похожих дисплеях.

**Add to display** в каталоге выбирает экран новой карточки. В **Arrange…** выберите карточку и используйте **Move to display** для переноса. Эти списки появляются при наличии нескольких доступных экранов. В **My widgets** перенос доступен и при одном подключённом экране, чтобы вернуть карточку с отключённого монитора. Перенос сохраняет ID и настройки; если места нет, карточка остаётся на прежнем экране, а окно объясняет отказ.

Доступная область учитывает текущую высоту включённой панели и резерв постоянно видимого Dock только на экранах, где он включён. Режимы скрытия Dock `smart` и `always` не резервируют площадь, как и в самом compositor. Отключение компонентов освобождает их резерв. Карточки дополнительно сохраняют отступы от краёв. Геометрия берётся в логических пикселях, включая поворот и дробный масштаб.

При временной нехватке места корректные желаемые ячейки получают приоритет; остальные карточки смещаются в свободные. Непоместившиеся и отключённые перечисляются в **My widgets** с именем сохранённого дисплея и причиной. Для подключённого экрана размер неразмещённой карточки можно уменьшить. Изменение разрешения, масштаба, резервов или состава экранов само по себе ничего не записывает. После восстановления геометрии исходная раскладка возвращается. Только явные действия добавления, переноса, размера и перетаскивания меняют желаемые координаты.

Примеры галереи: [тёмная тема](images/widgets-displays-dark.png), [светлая тема](images/widgets-displays-light.png).

Для диагностики без записи: `macshell-niri ipc call widgets layout`. Команда показывает доступные прямоугольники, профили, размещённые и неразмещённые экземпляры.

Модельные проверки покрывают два экрана, перестановку, отключение/возврат, смену разъёма с serial, отрицательные координаты, дробную геометрию, поворот, полную сетку и неоднозначные профили. Отдельный тест реального контроллера и писателя использует синтетические дисплеи без desktop-поверхностей. Реальные mask, reflow при изменении резерва и focus проверены в niri на одном физическом экране; физическая многомониторная проверка пока не выполнена.

## Запись и восстановление

Единственный писатель — `WidgetPreferences` / `widget_layout_service.py`. Хранилище использует атомарную замену, права 0600, ревизию и проверку содержимого файла перед записью. Устаревший контроллер получает отказ и текущее состояние; **Reload** перечитывает файл. Обычная повторная загрузка и no-op не переписывают его.

- `settings.before-v1-*.json` — точный исходный файл перед миграцией.
- `settings.previous.json` — предыдущая сохранённая версия.
- `settings.recovery-*.json` — файл перед подтверждённым сбросом.

Повреждённый файл или неверные записи открываются без перезаписи. **Reset widgets…** требует подтверждения, удаляет сохранённые карточки и сбрасывает общие параметры; исходный файл копируется. Формат более новой версии доступен только для чтения, кнопка сброса для него не предлагается. Примеры подтверждения восстановления: [тёмная тема](images/widgets-recovery-dark.png), [светлая тема](images/widgets-recovery-light.png).

Для возврата старого кода используйте совместимую копию настроек при остановленной оболочке. Сам по себе откат исходников не отменяет изменения файла настроек. Исходные плоские поля также сохранены в документе версии 1 как снимок перед миграцией; последующие действия работают с `values`.

## Подписки и отрисовка

Desktop-карточка и её отражения учитываются как один потребитель по ID. Weather и выбранный MPRIS Player по-прежнему общие: дубликат не запускает отдельный процесс. У Clock один общий источник времени с частотой самого требовательного видимого экземпляра: 33 мс для Smooth, 1 с для Once per second/Hidden, 30 с для одного Calendar. Данные для минут и календарной даты меняются только при соответствующей смене времени. При отсутствии потребителей источник останавливается; ClockApp имеет отдельный жизненный цикл таймеров/будильников.

Невидимые отражения и карточки под подтверждённым fullscreen на активном output сохраняют последний снимок данных, останавливают анимации, часы и шейдеры. При показе синхронизируются с текущим состоянием. Обычные окна с неизвестной геометрией не считаются полным перекрытием. Overview и Arrange восстанавливают обновления. Удаление, выключение и отключение output освобождают подписки; сохраняемые настройки отключённого экрана остаются на месте.

Прогноз кэшируется на 15 минут; повторный показ свежих данных обходится без запроса. Последний потребитель отменяет текущий Weather/LRCLIB процесс и отложенное обновление, поколение запроса отклоняет поздний ответ. При ошибке Weather повторяется через минуту при наличии видимой карточки. Lyrics запрашиваются только при открытом тексте M/L Player; позиция опрашивается раз в секунду или раз в 250 мс при открытых Lyrics и останавливается без активных Player.

Условия Qt для [Binding](https://doc.qt.io/qt-6/qml-qtqml-binding.html) не заменяют остановку вычислений значения: здесь используются условные снимки данных. Для отмены запрос выполняется в одном Rust [Process](https://quickshell.org/docs/v0.3.2/types/Quickshell.Io/Process/); при отсутствии совместимого бинарника используется Python fallback.

Диагностика без изменения настроек и запросов к сети:

```bash
~/.local/bin/macshell-niri ipc call widgets resources
```

Реализация M2 (T13–T19) завершена. Физическая multi-monitor/hotplug приёмка остаётся открытой: доступен один экран. T20 — Desktop Activity и T21 — Batteries реализованы; далее T22 — правила времени Timer; дополнительные города Weather и закреплённый Player по экземплярам остаются отдельными задачами.

Открыть галерею через IPC:

```bash
~/.local/bin/macshell-niri ipc call settings pane widgets
```

Обновления общей темы и читаемость Liquid-карточек описаны в [настройках оформления](APPEARANCE.md). Изменение темы сохраняет ID, позиции, размеры и явно выбранные стили экземпляров.
