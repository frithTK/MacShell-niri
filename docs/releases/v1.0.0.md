# MacShell-niri 1.0.0

The first full release: a macOS-inspired desktop for niri, with Liquid Glass, a Dock, Spotlight and a Control Center.

[See the interface](https://github.com/frithTK/MacShell-niri/blob/v1.0.0/README.md) · [Русский](https://github.com/frithTK/MacShell-niri/blob/v1.0.0/README.ru.md)

## Included

- Light and dark themes, adjustable glass, wallpapers, notifications, tray and app switching.
- Weather, Calendar, Clock and Player widgets, with individual styling, S/M/L sizes, duplication and display placement.
- A customizable menu bar and Activity graphs for CPU, memory, network and disk.
- Wi-Fi, Bluetooth, audio devices, application volume up to 150%, battery and power profiles.
- Focus, Keep Awake, Night Shift, screen recording and the separate MacLock screen locker.
- Optional AirPlay in both directions and AirDrop on supported Shared setups.
- Installation with backups, rollback and a separate Niri (MacShell) login session.

## Install

This is a **source release for Linux**. It needs niri 26.04+, Qt 6.9+ and a compatible Quickshell build. Runtime dependencies and optional AirPlay/AirDrop backends are installed separately.

Download `MacShell-niri-1.0.0.tar.gz` or `.zip`, extract it and start with:

```bash
bash install.sh --check
bash install.sh --dry-run --session
```

Follow the [installation guide](https://github.com/frithTK/MacShell-niri/blob/v1.0.0/docs/INSTALL.md) or [русское руководство](https://github.com/frithTK/MacShell-niri/blob/v1.0.0/docs/INSTALL.ru.md) to finish setup. `SHA256SUMS` contains checksums for both archives.

Existing checkouts should be cloned afresh: this release starts a new Git history. The installed settings can be kept. [Details](https://github.com/frithTK/MacShell-niri/blob/v1.0.0/docs/HISTORY.md).

## Tested scope

The release passes 195 Python tests, 397 QML checks, QML/shader compilation and isolated service/installer checks. Native interface checks cover both themes, widget input and lifecycle; GitHub CI also checks Qt 6.9.3 and isolated Owly transfers.


Physical multi-monitor/hotplug acceptance remains open. AirDrop needs a compatible Shared setup; exclusive modes that interrupt Wi-Fi are blocked. AirPlay, audio, capture, power controls and PAM unlocking depend on the installed backends and hardware.
